**Media Vault Bot** — это асинхронный Telegram-бот, разработанный как персональная медиатека пользователя. Проект позволяет структурированно сохранять, категоризировать, просматривать и удалять информацию о фильмах, сериалах, изображениях и документах.

Вся логика построена на современном стеке **Aiogram 3.x** и асинхронной работе с базами данных через **SQLAlchemy 2.0 (PostgreSQL)**.

---

## 🔥 Ключевые возможности

- 🔐 **Автоматическая регистрация:** При отправке команды `/start` бот проверяет наличие пользователя в базе данных и, если его нет, автоматически регистрирует, сохраняя его Telegram ID и имя.
- 🗂 **Категоризация контента:** Раздельное хранение данных по 4 направлениям:
  - Фильмы (с указанием названия, текстового комментария и жанра).
  - Сериалы (с поддержкой специфичных жанров, таких как ситкомы).
  - Изображения (бинарное хранение файлов `BYTEA` с разделением по важности).
  - Документы (бинарное хранение файлов с описанием).
- 🧭 **Интерактивное меню:** Полностью динамический интерфейс на инлайн-кнопках (Inline Keyboards) со сквозной навигацией и кнопками возврата «Назад».
- 📄 **Умная пагинация:** Списки выгружаются порционно (по 3 элемента), не перегружая интерфейс чата. Перелистывание страниц реализовано через кастомные фабрики `CallbackData`.
- 📥 **Пошаговый ввод (FSM):** Интуитивное добавление контента через машину состояний (Finite State Machine) с валидацией типов данных на каждом шаге.
- 🗑 **Безопасное удаление:** Реализован механизм мягкого или каскадного удаления записей из персональной коллекции.

## 🛠 Технологический стек

- **Язык программирования:** Python 3.10+
- **Фреймворк бота:** `aiogram 3.x` (Асинхронный Event Loop, Routers, FSM Context)
- **ORM:** `SQLAlchemy 2.0` (Асинхронные сессии, Declarative Base, `Mapped` типизация)
- **База данных:** `PostgreSQL` via `asyncpg` (поддержка типов данных `ENUM` и `BYTEA` на уровне СУБД)
- **Валидация и конфиг:** `pydantic`, `pydantic-settings`

## 📊 Структура базы данных (Модели данных)

База данных состоит из пяти сущностей, связанных между собой связью **Один ко Многим (1:M)** по внешнему ключу `user_id` с каскадным удалением (`ondelete="CASCADE"`):

- **Users (`users`):** `id` (Telegram ID), `username`, `created_at`.
- **Films (`user_films`):** Название (до 100 символов), текстовый комментарий, жанр (`GenreFilms`), флаг удаления `is_deleted`.
- **Serials (`user_serials`):** Название, комментарий, жанр (`GenreSerials`), флаг удаления.
- **Pictures (`user_pictures`):** Комментарий, статус важности (`PictureGenre`), бинарные данные картинки (`BYTEA`).
- **Documents (`user_documents`):** Название, описание, бинарные данные документа (`BYTEA`).
